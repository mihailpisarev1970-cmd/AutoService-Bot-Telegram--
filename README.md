## 📖 О проекте

**AutoService-Bot** — это полноценное решение для автосервиса, которое автоматизирует взаимодействие с клиентами прямо в Telegram. Бот не только записывает на ТО, но и выступает в роли умного помощника-диагноста, работающего с текстом, голосом и фотографиями.

### 🎯 Ключевые задачи, которые решает бот:

| Задача | Решение |
|---|---|
| 📅 Запись клиентов | Календарь со свободными слотами в реальном времени |
| 🔧 Проверка занятости | Асинхронный запрос к CRM Baserow перед показом слотов |
| 🤖 Первичная диагностика | Мультимодальный ИИ (текст + голос + фото) |
| 📊 Учёт обращений | Автоматическое создание записей в CRM с привязкой к Telegram ID |
| 📍 Информирование | Адрес, карты, прайс-лист, связь с мастером |
| 🔍 Статус ремонта | Клиент видит текущий статус своей заявки |

## ✨ Возможности

<details>
<summary><b>📅 Запись на ТО (нажмите, чтобы раскрыть)</b></summary>

- Интерактивный **календарь** с текущим месяцем и навигацией.
- Отображение **только свободных слотов** (проверка через Baserow).
- Занятые дни помечаются значком ❌, прошедшие даты — недоступны.
- Пошаговый сбор данных: **имя → автомобиль → описание проблемы**.
- Автоматическая запись в CRM с временной зоной **+03:00 (МСК)**.
- Краткое подтверждение записи с датой, временем и деталями.

</details>

<details>
<summary><b>🤖 ИИ-диагностика (нажмите, чтобы раскрыть)</b></summary>

Бот принимает **три типа входных данных**:

| Тип | Технология | Что делает |
|---|---|---|
| 📝 Текст | GPT-4o-mini | Анализ симптомов по описанию |
| 🎤 Голос | Whisper (OpenAI) | Транскрипция речи + анализ |
| 📸 Фото | GPT-4o-mini Vision | Анализ приборной панели / узлов |

**Структура ответа ИИ:**
1. 🔧 **Вероятные причины** — 2-3 самые частые поломки при таких симптомах
2. ⚠️ **Опасность для авто** — можно ли ехать или нужен эвакуатор
3. 🔍 **Что проверим в сервисе** — конкретные узлы для диагностики
4. 📞 **Призыв к действию** — запись на осмотр

</details>

<details>
<summary><b>🔍 Статус ремонта (нажмите, чтобы раскрыть)</b></summary>

- Бот ищет **последнюю запись** клиента по его Telegram ID.
- Извлекает данные из заметок (формат `[TG:123456789] описание`).
- Отображает: дату, время, авто, причину обращения и **текущий статус**.
- Поддерживает разные форматы статусов из Baserow (строка, список, объект).

</details>

<details>
<summary><b>📍 Дополнительные функции</b></summary>

- **Адрес и контакты** — карточка места с координатами.
- **Яндекс.Карты и 2ГИС** — кнопки-ссылки на карты с меткой.
- **Прайс-лист** — ориентировочная стоимость основных услуг.
- **Связь с дежурным мастером** — Telegram и телефон.

</details>

## 🏗 Архитектура

### Общая схема работы

```text
┌──────────────────────────────────────────────────────────────────┐
│                      👤 ПОЛЬЗОВАТЕЛЬ (Telegram)                   │
└───────────────────────────────┬──────────────────────────────────┘
                                │
                                ▼
┌──────────────────────────────────────────────────────────────────┐
│                     🤖 БОТ (aiogram v3)                           │
│  ┌────────────────────────────────────────────────────────┐      │
│  │  Handlers → FSM States → Keyboards (Inline/Reply)      │      │
│  └────────────────────────────────────────────────────────┘      │
└───────┬──────────────────────────────┬───────────────────────────┘
        │                              │
        │ (1) Запись / Статус          │ (2) Диагностика
        ▼                              ▼
┌─────────────────────┐        ┌─────────────────────┐
│   🗄 BASEROW CRM     │        │   🧠 POLZA.AI API    │
│                     │        │                     │
│  • Создание записей │        │  • GPT-4o-mini      │
│  • Проверка слотов  │        │  • Whisper (voice)  │
│  • Чтение статусов  │        │  • Vision (photo)   │
└─────────────────────┘        └─────────────────────┘
        ▲
        │
        │ (3) FSM Storage
        ▼
┌─────────────────────┐
│   ⚡ REDIS 7         │
│  (состояния FSM)    │
└─────────────────────┘
```

### Логика записи на ТО

```text
Пользователь → "📅 Записаться на ТО"
        │
        ▼
Показ календаря (текущий месяц)
        │
        ▼
Выбор даты (callback: date:YYYY-MM-DD)
        │
        ▼
Запрос в Baserow: get_appointments_by_date(date)
        │
        ▼
Фильтрация свободных слотов (09:00, 11:00, 13:00, 15:00, 17:00, 19:00)
        │
        ├── Нет слотов → "Все занято, выберите другую дату"
        │
        ▼
Показ свободных слотов (Inline-кнопки)
        │
        ▼
Выбор времени → Ввод имени → Ввод авто → Ввод проблемы
        │
        ▼
create_appointment() → Baserow (POST /rows/table/278)
        │
        ▼
✅ Подтверждение записи пользователю
```

## 🚀 Установка

### Предварительные требования

- **Python** 3.10 или выше
- **Docker** и **Docker Compose** (для запуска через контейнеры)
- **Redis** 7 (поднимается автоматически в Docker)
- Аккаунт в **Baserow** с таблицей и API-токеном
- API-ключ **Polza.ai** (или OpenAI)

### 1️⃣ Клонирование репозитория

```bash
git clone https://github.com/your_username/autoservice-bot.git
cd autoservice-bot
```

### 2️⃣ Настройка окружения

Создайте файл `.env` на основе шаблона:

```bash
cp .env.example .env
```

Откройте `.env` и заполните переменные:

```env
# ===== TELEGRAM =====
BOT_TOKEN=1234567890:ABCdefGHIjklMNOpqrsTUVwxyz

# ===== POLZA.AI (ИИ-диагностика) =====
POLZA_API_KEY=sk-xxxxxxxxxxxxxxxxxxxxxxxx
POLZA_BASE_URL=https://api.polza.ai/v1
AI_MODEL=openai/gpt-4o-mini

# ===== REDIS (FSM) =====
REDIS_HOST=redis
REDIS_PORT=6379

# ===== BASEROW (CRM) =====
BASEROW_URL=https://crm.pisarev-n8n.ru
BASEROW_TOKEN=your_baserow_api_token
BASEROW_TABLE_ID=278
```

<details>
<summary><b>🔑 Где взять каждый ключ?</b></summary>

| Переменная | Где получить |
|---|---|
| `BOT_TOKEN` | Telegram → [@BotFather](https://t.me/BotFather) → `/newbot` |
| `POLZA_API_KEY` | [polza.ai](https://polza.ai) → Личный кабинет → API-ключи |
| `BASEROW_TOKEN` | Baserow → Настройки базы → API-токены |
| `BASEROW_TABLE_ID` | ID таблицы из URL: `.../table/278/...` |

</details>

### 3️⃣ Запуск через Docker (рекомендуется)

```bash
docker-compose up -d --build
```

Проверить статус:

```bash
docker-compose ps
docker-compose logs -f bot
```

Остановить:

```bash
docker-compose down
```

### 4️⃣ Локальный запуск (без Docker)

```bash
# Создание виртуального окружения
python -m venv venv

# Активация
source venv/bin/activate       # Linux / macOS
venv\Scripts\activate          # Windows

# Установка зависимостей
pip install -r requirements.txt

# Запуск
python main.py
```

> 💡 Для локального запуска убедитесь, что Redis доступен (например, через `docker run -d -p 6379:6379 redis:7-alpine`), и укажите `REDIS_HOST=localhost` в `.env`.

## 🐳 Docker Compose

Файл `docker-compose.yml` поднимает два сервиса:

| Сервис | Образ | Назначение |
|---|---|---|
| `redis` | `redis:7-alpine` | Хранилище FSM-состояний |
| `bot` | Собран из `Dockerfile` | Telegram-бот на aiogram v3 |

**Особенности:**
- Автоматический рестарт при падении (`restart: always`)
- Часовой пояс `Europe/Moscow` для корректной работы с датами
- Зависимость `depends_on: redis` — бот стартует после Redis

## 🔄 Основные сценарии

### Сценарий 1: Клиент записывается на ТО

```text
1. Пользователь: /start
2. Бот: Показывает главное меню
3. Пользователь: "📅 Записаться на ТО"
4. Бот: Показывает календарь
5. Пользователь: Выбирает дату → "15"
6. Бот: Запрашивает Baserow, показывает свободные слоты
7. Пользователь: Выбирает "11:00"
8. Бот: Запрашивает имя → авто → проблему
9. Пользователь: Вводит данные
10. Бот: Создает запись в Baserow, подтверждает
```

### Сценарий 2: Клиент проходит ИИ-диагностику

```text
1. Пользователь: "🤖 ИИ-диагностика"
2. Бот: Просит описать проблему
3. Пользователь: Отправляет голосовое сообщение
4. Бот: 
   - Скачивает аудио
   - Отправляет в Whisper → получает текст
   - Отправляет текст в GPT-4o-mini
5. Бот: Возвращает структурированный диагноз
```

### Сценарий 3: Клиент проверяет статус

```text
1. Пользователь: "🔍 Статус ремонта"
2. Бот:
   - Запрашивает все записи из Baserow
   - Фильтрует по Telegram ID из заметок
   - Берет последнюю запись
3. Бот: Показывает статус, дату, авто и причину
```

## 🐛 Известные особенности

<details>
<summary><b>Обработка часовых поясов</b></summary>

Baserow может хранить время в UTC. В `handlers.py` при создании записи явно указывается смещение:

```python
iso_datetime = f"{data['chosen_date']}T{time_part}:00+03:00"
```

Это гарантирует, что время в CRM совпадает с московским.
</details>

<details>
<summary><b>Сжатие фотографий</b></summary>

Перед отправкой в Vision API фото сжимается через Pillow:
- Максимальная сторона: **1024px**
- Формат: **JPEG**
- Качество: **75%**
- Оптимизация: **включена**

Это уменьшает стоимость запроса и ускоряет ответ.
</details>

<details>
<summary><b>Дубликаты модулей</b></summary>

В проекте есть две версии логики:
- **Монолитная** — `handlers.py` (используется сейчас)
- **Модульная** — `ai_diag.py` + `common.py` + `ai_service.py` (архив)

При рефакторинге рекомендуется оставить одну версию.
</details>
